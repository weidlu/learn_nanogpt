GPT 心智模型

一句话版本：给它一串 token，它对每个位置预测“下一个 token 应该是谁”。

1. 文本`To be` 这种字符串。
2. 编码字符或 BPE token 变成整数。
3. 嵌入整数查表，变成向量。
4. Transformer用上下文混合信息。
5. logits给词表里每个 token 打分。
6. 采样选一个 token 接到末尾。

Token 小玩具

这里用“字符级 token”演示，和 `data/shakespeare_char/prepare.py` 的思路一样：每种字符分配一个整数 id。

这个项目里有两种编码

字符级：`shakespeare_char` 只有约 65 个 token，适合新手快速训练。

GPT-2 BPE：`openwebtext` 和普通 GPT-2 使用 `tiktoken`，词表约 50k。

先学字符级模型最舒服：token 就是字符，少了一层 tokenizer 的魔法烟雾。

Causal Attention 小演示

点一个 token，看它在 GPT 里能“看见”谁。未来位置会被 mask 掉，所以模型训练时不能偷看答案。

注意力公式的直觉

Query：我现在想找什么信息？

Key：每个历史 token 声明自己有什么信息。

Value：真正被加权拿走的内容。

att = softmax(q @ k.T / sqrt(head_size))
y = att @ v

训练循环

训练不是“教它知识点”，而是重复调整参数，让它更会预测下一个 token。

按一次，走一步训练

`train.py` 的主线

1. 读取 config 和命令行覆盖。

2. 从 `train.bin` / `val.bin` 采样 batch。

3. 初始化模型：scratch、resume 或 GPT-2。

4. forward 得到 loss，backward 得到梯度。

5. AdamW 更新参数，定期评估和保存。

拖一拖参数，感受 `n_layer`、`n_head`、`n_embd`、`block_size` 怎样影响模型大小和每轮吞掉的 token 数。参数量是粗估，用来培养直觉，不替代真实打印值。

生成文本

生成时没有梯度，只有一个循环：预测、采样、追加、再预测。

`generate()` 的 6 步

idx_cond = idx[:, -block_size:]
logits, _ = model(idx_cond)
logits = logits[:, -1, :] / temperature
logits = keep_only_top_k(logits)
probs = softmax(logits)
idx = cat(idx, sample(probs))

两个采样旋钮

temperature 越低越保守，越高越发散。

top_k 只保留最可能的 k 个候选，避免太离谱的 token 混进来。

它不是一次性吐出整段话，而是像搭积木一样，一个 token 一个 token 往后接。

自测 1

为什么 GPT 训练目标是“预测下一个 token”？

因为大量文本天然提供监督信号。给前文 `x`，真实下一个 token 就是标签 `y`。不需要人工标注，整本书都能变成训练样本。

自测 2

为什么 attention 要 causal mask？

训练时模型同时处理一整段序列。如果不 mask，它会看到未来 token，loss 会变得虚假地低，生成时却没有未来可看。

自测 3

`block_size` 是什么？

它是模型一次最多看的上下文长度。更大能看更远，但 attention 计算和显存压力也会明显上升。
